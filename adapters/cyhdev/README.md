# cyhdev integration snapshot

This directory preserves the complete Minecraft feature source from [cyhdev](https://github.com/younghyun1/cyhdev) without copying the rest of the website. It includes the map/control backend, squaremap file cache, public and administrator pages, map components, generated Minecraft contracts, styles, browser fixtures, unit tests and waypoint migration/tests. Relative source paths match the original application.

[`SOURCE_SNAPSHOT.json`](SOURCE_SNAPSHOT.json) records original relative paths and SHA-256 hashes for the exact source copies. The extracted Minecraft schema declarations have a separate entry because the unrelated host schema is intentionally omitted. Commit provenance is recorded in [source origins](../../docs/source-origins.md).

These are host adapters, not independently compilable applications. `Cargo.reference.toml` and `package.reference.json` record the host dependency definitions; they are deliberately not build manifests. The buildable reusable sampler, wire codec and browser package live under `crates/seed`, `crates/tile-codec` and `packages/map-ui`. Renderer code appears both in the exact host snapshot and the extracted package so the existing consumer can be reviewed without silently changing its imports.

Backend imports require the host account authorization service, error/response envelopes, ServerState composition root, database pool/schema, timing helpers and middleware. The current account service takes database-current administrator authority before waypoint/control mutations. Do not replace this with browser state or a cached role check.

The frontend requires the host session-aware `contractApi`, generated runtime/index exports, `isSuperuser`, translation state, admin shell and global CSS variables. It keeps lazy routes `/minecraft` and `/admin/minecraft`; both still belong to the host router. Generated Minecraft contracts are preserved verbatim; their host-level barrel exports are not copied because they include unrelated website features.

Backend registration belongs in `src/routers/main_router.rs`: merge public map routes, merge control/waypoint mutations under the existing administrator/origin guards, and mount the squaremap asset router. Add the Minecraft waypoint service to `src/init/state/{builder,server_state,server_state/core}.rs`. The Diesel schema needs the two declarations in `backend/src/schema_minecraft.rs`; apply the included migration through the host migration owner. Register Minecraft endpoint/types in `src/docs.rs` and `src/openapi_codegen/{surface,router_surface}.rs`, and preserve binary response handling and browser-policy/deadline tests.

The original main router declares `mod compression`, constructs `compression::layer()` and applies it before the outer host HTTP policy. Preserve that helper's binary MIME exclusion: the map binary route owns its gzip-only compression layer in `seed_tile_compression.rs`, while unrelated host routes keep their existing encoding negotiation. `compression_tests.rs` exercises the real layers and the copied `middleware/sensitive_response.rs` policy, including private headers, negotiated gzip and prevention of double compression. These helpers remain part of the host adapter rather than the standalone codec crate.

Host UI wiring also touches `src/routes.ts`, public/admin navigation, localization keys/defaults, generated exports and shared API transport. Host Docker/packaging must include the seed worker only while legacy compatibility is configured and must ship its GPL notices. These integration points remain in the original application; this snapshot does not replace or deploy that application.

No production configuration, database contents, secrets, world data, map tiles or logs are included. Tests use controlled fixtures. The administrator control transport remains loopback WebSocket plus the same-user Unix-socket visibility plugin; the static squaremap cache has its independent four-GiB total budget, and predictions retain their separate 512-MiB budget.
