# Minecraft Wiki chat

`/ask` uses the Paper server thread only for permission checks, bounded admission, sender identity, and final private chat delivery. A single background worker owns a persistent Rust child. That child holds an immutable memory-mapped Tantivy index and a persistent `codex app-server --stdio` process. Inherited JSON pipes avoid process startup on subsequent questions, local TCP authentication, and an extra service to manage.

Each question makes one title-boosted BM25 lookup before inference. At most six 1,800-character passages accompany the question, player UUID/username, and world UUID/name. Short follow-ups add the previous question to the lookup while reusing the world's shared conversation. Players in the same world share context with attributed speakers; different worlds remain isolated. No model-driven search loop runs. GPT-6 Luna with low reasoning and fast service tier produces a final paragraph; both language boundaries enforce 60 words and 360 characters. Reasoning, commentary, tools, and partial output are not part of the game response protocol.

The bridge admits one in-flight question and retains at most 32 world conversations. Each conversation has a 32,768-token context setting and a 24,000-token compaction threshold; a four-byte-per-token text estimate is about 4 MiB across all retained contexts before JSON/object overhead, model-client state, and the memory-mapped index. This is a text estimate, not an RSS limit or a maximum bytes-per-token guarantee. Sessions stay available for the process lifetime without idle expiry. At capacity, new worlds are rejected without evicting existing context. Restarts reset ephemeral conversations. The next request after a transport/model error creates a new process; failed charged requests are never replayed automatically. Java adds a 43-second watchdog over the 20-second initialization, five-second session acquisition, and 15-second model deadlines.

The importer separately enumerates content and transclusion namespaces through the public MediaWiki API. Complete current revision text is stored in Zstandard batches with attribution and a resumable manifest. Only a complete snapshot can produce a serveable index. Refreshes build a new immutable directory; failed work cannot replace the active index. Downloads and credentials stay outside the repository. No data from a live Minecraft server is needed for acquisition or tests.
