# Minecraft Wiki chat

`/ask` uses the Paper server thread only for permission checks, bounded admission, sender identity, and shared chat delivery. Accepted questions appear with the sender's username, followed by the final short answer. Every recipient must be online, in the originating world, and hold `wikiask.use`; rejected requests receive private status replies. A single background worker owns a persistent Rust child. Plugin startup loads all decompressed wiki revisions and the immutable Tantivy index into RAM and initializes a persistent `codex app-server --stdio` process. Inherited JSON pipes avoid process startup on questions, local TCP authentication, and an extra service to manage. No corpus or index disk reads occur on the serving path after startup.

Each question makes one title/redirect-boosted BM25 lookup before inference. At most six 1,800-character passages accompany the question, player UUID/username, and world UUID/name. Short follow-ups add the previous question to the lookup while reusing the world's shared conversation. Players in the same world share context with attributed speakers; different worlds remain isolated. The two wiki-only dynamic tools allow up to three fallback calls: ranked retrieval, literal/regex scans with continuation cursors, and 6,000-character revision windows. Luna's isolated code-mode host exposes these calls; environment access, shell tools, browser, apps, and plugins remain disabled. Tool results return only to the active model turn. GPT-6 Luna with low reasoning and fast service tier produces a final paragraph; both language boundaries enforce 60 words and 360 characters. Reasoning, commentary, tools, and partial output are not part of the game response protocol.

The September 29 snapshot uses 152.05 MiB of text plus an 88.19 MiB index. Startup rejects text allocations above 256 MiB, title/timestamp allocations above 16 MiB, more than 100,000 pages, or index files above 128 MiB. This gives 400 MiB of maximum retained payload allocations, plus page/revision structures, readers, eight decompressed store-cache blocks per segment, batch decoding, and allocator overhead. Index loading precedes text loading so index-copy scratch space does not overlap the full resident text. The measured development bridge used 319.97 MiB RSS immediately after loading; budget 512 MiB for this snapshot's bridge, with Codex and its code-mode child budgeted separately. This planning allowance is not an OS-enforced RSS limit. These budgets do not replace or consume the map prediction and squaremap budgets. [Measurements](../../benchmarks/wiki-ask.md) separate startup, warm lookup, and inference.

The bridge admits one in-flight question and retains at most 32 world conversations. Each conversation has a 32,768-token context setting and a 24,000-token compaction threshold. Sessions stay available for the process lifetime without idle expiry. At capacity, new worlds are rejected without evicting existing context. Restarts reset ephemeral conversations. The next request after a transport/model error creates a new process; failed charged requests are never replayed automatically. Java adds a 43-second watchdog over the 20-second initialization, five-second session acquisition, and 15-second model deadlines, including fallback calls. Initialization and requests run on the same worker; disable permanently prevents further child startup and terminates only the plugin's process tree.

Operators with `wikiask.use` can invoke `/ask clear` or `/ask compact` for their current world. Bukkit checks operator status before admission; non-operators cannot tab-complete the controls. Explicit JSON actions bypass gameplay inference and retrieval. Clear unsubscribes the retired thread and removes its retrieval follow-up; compact retains the session and waits for its successful compaction item and turn completion. Controls share the cooldown and busy gate, with a 35-second operation deadline and 60-second outer watchdog. Other worlds are untouched on successful control operations; transport failures retain the existing process-reset policy.

The importer separately enumerates content and transclusion namespaces through the public MediaWiki API. Complete current revision text is stored in Zstandard batches with attribution and a resumable manifest. Only a complete snapshot can produce a serveable index, and the corpus/index manifests must match before serving. Refreshes build a new immutable directory; failed work cannot replace the active index. Downloads and credentials stay outside the repository. No data from a live Minecraft server is needed for acquisition or tests.
