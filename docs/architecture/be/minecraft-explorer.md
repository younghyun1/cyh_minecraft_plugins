# Minecraft terrain explorer

The public `/minecraft` explorer reuses squaremap's rendered tiles and published player snapshots. Its own Leaflet client never executes the generated map's JavaScript. The retired `/minecraft/map`, `/minecraft/map/`, and `/minecraft/map/index.html` entries redirect to `/minecraft`; that namespace serves only canonical JSON/PNG tile data and PNG images needed by the native client. Legacy HTML, JavaScript and CSS are unavailable. Public map observations and waypoint reads are independent of administrator server controls.

## World observations

`POST /api/minecraft/map/query` accepts a closed `catalog`, `area`, or `blocks` request. `MINECRAFT_WORLD_SOCKET` selects the same-user Unix socket exposed by the Paper plugin; an absent setting disables observations while leaving squaremap browsing available. Requests contain dimension keys and coordinates, never filesystem paths or commands. The Rust service bounds request and response frames to 4096 bytes and 2 MiB, uses a single nonwaiting operation slot, imposes a one-second cooldown, and applies a twenty-second deadline. A cancelled operation retains its reservation until twenty-one seconds after it began so another request cannot overlap game-side work. The plugin has a fifteen-second deadline and a socket with mode `0600` inside the existing mode `0700` directory.

The catalog contains at most sixteen squaremap-enabled worlds and 4096 block identifiers. Area queries cover at most eight by eight chunks and return up to 1024 four-block samples and 256 generated structures. Each sample contains surface elevation and a biome; an optional Y value selects the biome slice without changing the elevation meaning. Block queries cover at most four by four chunks, an inclusive vertical range of at most 512 blocks, and at most 512 exact matches. Empty or missing chunks are counted rather than generated. Incomplete results carry a truncation flag and every response carries its sampling timestamp.

Chunk loading uses Paper's asynchronous non-generating API, with one load outstanding and at most one snapshot scheduled per tick. Snapshot analysis occurs on the dedicated worker. No full-world index, continuous pan-triggered scan, or unbounded cache is introduced. Results are area observations rather than claims about the entire dimension.

The browser's terrain inspection reuses survey data and permitted seed predictions before issuing a debounced one-chunk surface query through the same area contract. Its separate observation cache is capped at 64 chunks with a 30-second lifetime. The browser serializes automatic and explicit world reads, retains only the latest hover target, and prioritizes explicit actions. No endpoint, server cache, chunk-generation behavior, or block-type inference is added for hover inspection.

## Saved structures

Paper's ordinary structure lookup follows reference chunks and can synchronously load them. The explorer instead reads each queried chunk's saved `structures.starts` metadata from the dimension-specific region directory. It combines the bounding boxes of saved structure pieces and never follows references into other chunks. A structure appears when its start chunk falls inside the scanned area; structure metadata reflects the last world save and may remain after players dismantle the structure.

The selective NBT reader caps compressed data at 1 MiB, decompressed data at 8 MiB, nesting at 64, and tag processing at 100,000. It validates chunk coordinates, bounding boxes, region allocations, file type, and header stability. It supports gzip, zlib, and uncompressed region chunks. Missing saves, external chunk storage, unsupported compression, malformed data, or detected concurrent header changes produce explicitly incomplete structure coverage rather than a false complete empty result.

## Waypoints

Waypoint reads are public and bounded to 256 records per dimension. Names and descriptions are plain text, bounded to eighty and five hundred characters; coordinates are restricted to supported world bounds. Creation, replacement, and deletion require the established session and trusted-origin guards and a database-current administrator authority lease held through the write.

The PostgreSQL repository serializes slot allocation using a dimension lock row. A unique dimension-and-slot constraint combined with slots restricted to zero through 255 enforces the capacity under concurrent writes. UUID identifiers use the database's UUIDv7 default. Waypoints are public shared map records, not copies of player identities or game-server data. No seed or management credential is returned to the browser.

## Predicted biomes

`POST /api/minecraft/map/seed-tile.bin` serves the continuous prediction base beneath squaremap using the [bounded CYBM protocol](minecraft-tile-protocol.md), with native HTTP gzip negotiation. Requests contain a canonical Overworld, Nether or End key, signed tile X/Z, level from zero through twelve, and Y within that dimension's build interval: -64 through 319 for the Overworld and zero through 255 for Nether and End. Every tile has 64 by 64 biome samples; level zero spans 256 blocks with a four-block sample step, and both dimensions double at each coarser level. Responses retain a palette, nullable indices, preset, timestamps and a public profile epoch for hover and permission checks. The browser never receives a seed or chooses the preset. The `/seed-tile.png` transport remains selectable; the earlier `/seed-tile` JSON representation remains for compatibility and contract generation. PNG uses the browser's image decoder and a bounded bitmap cache, with comparable measured viewport latency and greater transfer size than compressed CYBM.

The backend links the [pinned Pumpkin sampler](../../../crates/seed/README.md) directly. One dedicated CPU worker retains its router and sampler for the effective seed/dimension/preset; an eight-job queue rejects overload. Nether sampling selects Paper's legacy temperature/vegetation initialization. End sampling adapts Pumpkin's simplex primitive to Paper's coordinate and floating-point arithmetic, correcting upstream far-coordinate overflow and fused-operation differences; a fixed 64-slot memo reuses biomes within End chunks. Synthetic Paper fixtures cover these adaptations. A private single-thread Rayon pool bounds retained density buffers. Cancellation skips obsolete queued jobs and is checked between rows. No Minecraft/Pumpkin server, preview world, process per tile, or chunk generation is involved.

The private `seed_profile` plugin request supplies the effective generator, world identity, and visibility policy. Three fixed dimension slots use asynchronous read/write locks and five-second freshness. Refreshes coalesce per dimension, use the shared observation reservation, survive caller cancellation, and have a sixteen-second deadline. Warm tiles never contact Paper or incur the analysis cooldown. Plugin 1.4.0 validates the effective dimension, vanilla settings and biome source for default/large-biomes Overworld, Nether and End, plus bounded function-only pack checks off the server thread. It exports at most 64 rectangle/circle visibility shapes intersected with the stationary world border. Unknown shapes, moving borders, incompatible generators, generation-changing packs and unavailable policy fail closed. Each coarse sample footprint must fit wholly inside the border and one visibility shape, or only the border when no shapes are configured. Adjacent or overlapping shapes can leave conservative blank coarse cells even where their union covers the cell.

Continuous tiles and the retained legacy preview cache share one 512 MiB process budget. Of this, 128 MiB reserves index, sampler and active-work headroom; retained palette payloads share the remaining 384 MiB through byte reservations. Admission reserves memory before cache retention; bounded in-flight generation allocations use the active-work headroom. Saturation evicts entries or bypasses caching. Keys include world UUID, private generator revision, seed, preset, coordinates/level, and Y. The linked engine revision is fixed for the backend process. Biomes remain cacheable independently of mutable permission masks; responses apply the current profile and expire no later than fifteen seconds after its sample. Public epochs change with world/profile/policy changes without exposing the private digest.

Actual squaremap PNGs render above predictions, and their alpha mask determines the thin rendered-terrain boundary and observed/predicted hover precedence. Transparent or unavailable imagery never grants visibility permission. Generated-but-unrendered terrain can show explicitly predicted biomes until squaremap renders it; predictions do not claim that a chunk is absent. World analysis and exact block matches remain separate observations. The existing `/api/minecraft/map/prediction` endpoint remains a compatibility path for the old bounded preview, with its original conservative chunk mask, cooldown and optional companion executable; the map no longer uses it.

The preview is approximate. Deterministic per-point biome-tree lookup avoids viewport-history dependence, but equally close biome candidates can differ from saved chunk traversal. Fixed-Y raw quart biomes do not reproduce squaremap's surface colors, Voronoi blending, blocks, structures, player modifications, or old-generation transitions. Actual observations and terrain retain their existing meaning. The [sampler documentation](../../../crates/seed/README.md) records independent fixture coverage and measured limitations.

## Activation and verification

Compile and install the updated [Paper plugin](../../../plugins/map-control/README.md), configure `MINECRAFT_WORLD_SOCKET` to its absolute `world.sock` path, apply the embedded waypoint migration, and deploy the website through the normal workflow. Local implementation does not install the plugin or restart Minecraft. Unset the new environment variable to disable observations without disabling the base map or existing controls.

Continuous predictions require the plugin's `seed_profile` protocol and a backend built with the sampler library; `MINECRAFT_WORLD_SOCKET` is the runtime configuration. `MINECRAFT_SEED_WORKER` applies only to the compatibility endpoint. Distribution layouts retain the sampler's GPL-3.0 license and third-party notices because the backend now links that code. Changing the linked engine requires a backend deployment, which also drops its cache. Installing a new plugin requires an explicitly approved Minecraft restart; local code verification never authorizes that restart.

The public catalog distinguishes configuration from transport failures. HTTP 503 with error code 86 means `MINECRAFT_WORLD_SOCKET` was absent from the backend process environment at startup; it does not indicate an unreadable socket. If the catalog succeeds but the legacy prediction endpoint returns the same disabled code, `MINECRAFT_SEED_WORKER` is absent. A configured but inaccessible socket, old plugin without the required protocol, unsupported generator profile, or failing sampler instead returns the map-unavailable error. Check the service's exported environment, socket existence and ownership, and executable permissions using the service account. An explicitly configured legacy worker path is still validated at backend startup; retain that optional binary or remove the old setting when retiring the legacy endpoint. Updating an environment file alone does not change a running process. Runtime activation must follow the approved service maintenance window. Do not expose seeds or management secrets while checking configuration.

The [integration snapshot](../../../adapters/cyhdev/README.md) preserves host checks and their dependencies. Pure Java fixtures cover protocol framing and saved-region decoding; Rust tests cover input/output bounds, socket behavior, and administrator guards; PostgreSQL tests cover persistence and database constraints; browser fixtures cover rendering, scanning, waypoints, and mobile layout.
