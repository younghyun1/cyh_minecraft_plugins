# Minecraft map

The public Minecraft page uses squaremap terrain with a native Leaflet client. Its scoped palette, beveled controls, square outlines, monospace labels, and pixelated terrain evoke Minecraft without importing another component framework. Terrain fills the space between the website bars on desktop and mobile. The dimension selector, refresh action, and compact tool buttons float on the map. Tools open by click and close through their toggle, close button, or Escape; no sidebar or atlas header remains. Native inputs, visible keyboard focus, coordinate navigation, and text result lists complement pointer interaction.

Home centers the current dimension at X 0, Z 0 while preserving zoom. The zoom control aligns with the dimension selector. A long scale bar sits at the bottom center of the map with quarter notches and intermediate labels; narrow screens show every other label. One block equals one metre, including in the Nether. The ruler accounts for squaremap's coordinate normalization, switches between metres and kilometres, uses readable 1/2/4/5/8 intervals, and updates on zoom and resize. Controls support keyboard activation without triggering terrain clicks or area selection.

Frozen rivers use icy cyan (`#8dd8e8`), separate from the pale snowy/ice biome group. The browser palette used by binary tiles and survey overlays matches the backend PNG encoder. Rendered squaremap imagery retains its original block colors.

The Layers menu surveys a selected area, shows biome colors or surface elevation, highlights chosen biomes, and lists saved structure starts. A click-open picker offers dimension-specific biomes as checkboxes, including multiple selections and a clear action. Selected biomes receive a translucent gold layer over permitted prediction tiles and any observed cells in the current survey; other map content stays visible. The overlay reuses the existing prediction tile store and exact biome indices, redraws cached tiles when selections change, and allocates no extra tile canvases when empty. Actual squaremap pixels contain no biome identities, so generated terrain outside an observed survey cannot be highlighted from its image alone. Select area enables pointer dragging over complete chunks, capped at 128 by 128 blocks; otherwise a survey uses that size around the selected point. A Y selector samples cave biomes while elevation continues to describe the surface. Gold outlines identify completed surveys; the next survey remains separately outlined. Coverage counts, time, and incomplete results stay visible. Structure bounds describe saved metadata and can outlast a demolished structure.

Predicted biomes are enabled by default for the Overworld, Nether, and End. Each Nether and End biome has a distinct palette color; the End is sampled as five biomes rather than a single fill. A persistent Leaflet canvas grid loads the visible map at every supported zoom, retaining current tiles during panning and zoom transitions. Each 256-pixel tile contains 64 by 64 samples; sample spacing doubles when zooming out, beginning at four blocks. Binary tiles are the default, with gzip negotiated by the browser HTTP stack. Versioned frames retain palette names and exact hover indices, using packed values or run lengths. The binary reader bounds the decompressed body to 40,000 bytes and rejects malformed metadata, indices, and trailing bytes before rendering. The optional PNG format uses native ImageBitmap decoding, with the same exact hover metadata in a validated cyBM chunk; its complete response is capped at 65,536 bytes. No JavaScript image or HTTP decompressor is used. Four concurrent requests serve visible tiles first, with a bounded low-priority neighboring ring prefetched. Prediction tiles remain 256 CSS pixels at every browser zoom, preserving the same seed level and detail for a fixed map zoom. The browser admits at most 2,048 active seed targets. Its tile-data budget starts at 16 MiB and grows by 128 KiB per active target to a 256 MiB ceiling, including a 32 KiB CPU/GPU reserve per native bitmap. A validated tile costs at most 116,736 bytes, below that reservation. Prediction and highlight layers each retain at most 2,048 small backing canvases, with a 64 MiB two-buffer reserve per layer. Eviction, expiry, cancellation, and disposal close owned bitmaps. Canceled native decode work retains its request admission until completion, so rapid format or dimension changes cannot exceed four decodes. Packed alpha masks use at most 2 MiB, packed frontier geometry at most 4 MiB, and drawing has a global 8,192-segment cap. Tile data and both canvas layers have a combined reserve of at most 384 MiB; DOM, object and driver overhead is additional. Normal viewports retain the 16 MiB tile budget. Two additional zoom-out levels scale the native squaremap overview beneath a coarser seed grid. A viewport-derived minimum zoom limits the native overview to 256 PNG tiles including its retained border; very wide viewports use fewer extra zoom levels. The seed service's maximum level of 12 also bounds the minimum. Native terrain URLs never request unsupported negative levels, and rendered hover and frontier coordinates retain the native zoom transform.

Seed tiles render beneath actual squaremap PNGs. Transparent pixels reveal predictions, while server-provided null samples independently enforce visibility permissions. A one-pixel black line marks actual/predicted transitions; shared tile edges and unknown neighbors do not create outlines. Frontier geometry is rebuilt only when an actual tile or its neighbor changes. The line hides during zoom transitions and returns after the canvas redraw at the settled zoom; same-zoom panning keeps it visible. The client refreshes permission-bearing tiles before their 15-second deadline, retains still-valid imagery during renewal, and clears expired samples if renewal fails. Dimension, sampling mode, Y, visibility, and profile changes invalidate the affected state. Overworld predictions default to Surface mode; the compact Biome view selector offers Underground with a retained Y, initially 64. Nether and End retain their fixed Y controls and do not offer Surface mode. Layers also retains the prediction toggle and persisted Binary/PNG selector, with the server-selected default, large-biomes, Nether, or End preset. Surface requests and responses use null Y; fixed slices use numeric Y, keeping their cache identities separate. CYBM v1 numeric frames remain supported; v2 adds the Overworld surface sentinel in the same header. PNG metadata carries the same distinction. Changing tile format clears cached imagery, invalidates pending replies, and reloads current targets. Switching dimensions clamps the retained Y to that world's bounds. The browser receives no seed. Predictions do not replace actual surface elevation or block-search results.

Hovering terrain shows coordinates and biome details independently of overlay visibility. Tapping or navigating to coordinates exposes the same readout. Existing survey samples take precedence over permitted, unexpired seed predictions. Rendered terrain requests observed data instead of substituting a seed sample. Predicted hover reads reuse the finest cached tile at the pointer and report its actual sample spacing. The panel labels observed versus predicted biomes, sample resolution, fixed biome sampling Y when applicable, and surface elevation at the sample origin when observed. Predicted surface biomes are labeled as approximate surface samples and never claim a predicted terrain height. Exact block names and Y coordinates come only from block-search matches at that X/Z; squaremap pixels cannot identify arbitrary blocks. The panel leaves pointer gestures unobstructed and does not announce continuous pointer updates through a live region.

When no reusable biome sample exists, a stationary hover requests one chunk after 500 milliseconds. The browser retains at most 64 chunk results for 30 seconds, including unavailable results, and shares a single request slot and one-second completion cooldown with explicit analysis actions. Seed tiles use their own bounded queue. Explicit actions have priority over pending hover work. Dimension changes, terrain refresh, and hiding invalidate hover data; pointer movement never cancels an in-flight server read or queues a trail of requests. Missing terrain and request failures remain explicit.

The Blocks menu searches a selected area of at most 64 by 64 blocks and an inclusive vertical range of at most 512 layers. A larger dragged selection produces a size error; without a custom selection the search uses 64 by 64 blocks around the selected point. Cyan markers and a result list identify exact matches; results stop at 512 and report truncation. Dimension changes discard old observations and ignore late responses. Surveys and block searches follow explicit actions. Terrain and published player snapshots refresh separately while visible; player labels show persistent names and configured head, health, and armor details. Refresh requests made while tiles load are coalesced and queued, with completion and missing-tile feedback. Base terrain does not wait for the world-analysis catalog.

Places are public shared waypoints, loaded automatically when world metadata becomes available even while all menus are closed. Gold nameplates remain visible beside their markers without hovering; clicking a marker opens its coordinates and description. Waypoint markers and names share a dedicated layer above player banners and below popups. A shared SVG renderer keeps the markers clickable while nameplates and empty layer space do not intercept map gestures. Administrator controls create, edit, and delete them; the backend independently checks current authority. A location link preserves the selected dimension and coordinates. Travel tools provide coordinate navigation, spawn navigation, a horizontal distance ruler, and Overworld/Nether coordinate conversion. The conversion estimates a portal location, not an established link.

The original squaremap document is retired. Its former entry URLs redirect to `/minecraft`; only canonical JSON and PNG data remain served. The native explorer uses text nodes for all Leaflet labels. Plugin catalog failure leaves terrain and coordinate tools available; waypoint editing and analysis remain unavailable until their world metadata loads.
